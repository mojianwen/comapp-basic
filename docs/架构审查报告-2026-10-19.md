## 一、结论（先看这里）

**项目已经跑起来了，链路完整可用。** 改名本身不用改代码，改的是三样东西：npm 工作区软链、锁文件里的旧路径、以及历史构建缓存 —— 这三样不处理，报错会伪装成"代码问题"，很难查。

| 维度 | 评价 | 说明 |
| --- | --- | --- |
| 技术架构 | **优** | 四层单向依赖（tokens ← components ← layouts ← 应用），业务与框架彻底分离，换主题只改变量 |
| 功能架构 | **良** | 路由/菜单/按钮三层权限闭合，RBAC 六表落库，系统管理三页走真实接口；业务页面尚为占位 |
| 工程质量 | **中上** | 22 例单测 + 23 断言 E2E + 21 断言冒烟 + ESLint/Prettier 全绿；**但仓库没有 git**，这是最大短板 |
| 运行基础条件 | **齐备** | Node 22 / PostgreSQL 5432 / 端口 5219+3000 全部就绪，登录链路实测通 |

**本次实测结果**：前端 HTTP 200、API `/health` ok、`demo/123456` 登录返回 token 与 15 个权限码、单测 22/22、Lint 0 错误、单文件构建 496.95 KB（gzip 143.72 KB）。

## 二、技术架构

### 2.1 层次与职责

| 层 | 目录 | 包名 | 技术栈 | 职责 | 对外形态 |
| --- | --- | --- | --- | --- | --- |
| 令牌层 | `packages/tokens` | `@mo/tokens` | 原生 CSS 变量 | `:root` 明 / `.dark` 暗两套语义色、圆角、阴影、动效 | `tokens.css` |
| 组件层 | `packages/components` | `@mo/components` | Vue 3.5 + Reka UI + Tailwind v4 + tailwind-merge | 26 组无样式封装组件 + `cn()` + Form 校验体系 + Toast 状态机 | `src/index.ts` 聚合导出 |
| 布局层 | `packages/layouts` | `@mo/layouts` | Vue 3.5 + 插槽 | `BasicLayout`（桌面固定侧栏 / <1024px 抽屉）、`PageSection`（20px 间距体系） | 具名插槽注入品牌区、侧栏卡、底部操作 |
| 应用层 | `apps/web` | `@mo/demo` | Vue 3.5 + Vite 6 + TS + vue-router 4（hash） | 登录、门户、组件示例、系统管理三页、错误页 | 浏览器 / 单文件 HTML |
| 服务层 | `apps/server` | `@mo/server` | Express 5 + pg（直写 SQL）+ JWT + bcryptjs + tsx watch | 认证、用户/角色/菜单 CRUD、权限实时校验 | REST `/api/*`，端口 3000 |

依赖方向严格单向，**没有反向引用**：

```
@mo/tokens  ←  @mo/components  ←  @mo/layouts  ←  apps/web
                                                  apps/server（独立，仅 HTTP 契约耦合）
```

### 2.2 三个关键机制（理解这三条，改代码就不会踩坑）

1. **npm workspaces + 符号链接**
   `node_modules/@mo/*` 全部是软链，指向各 `packages/*`、`apps/*` 的真实目录。**目录一改名或搬家，软链就成了死链**，Vite 报"依赖无法解析"，但依赖其实装得好好的 —— 重跑 `npm install` 即可重建。

2. **hash 路由 + 单文件构建**
   路由用 `createWebHashHistory()`，配合 `vite-plugin-singlefile` 把所有 JS/CSS 内联成一个 `index.html`，可以直接 `file://` 打开或扔进内网静态目录 —— 这是给离线/内网分发留的后路，不是没配置好 History 模式。

3. **主题即变量**
   组件里只写语义类名（`bg-background`、`text-muted-foreground`），颜色全部来自 `tokens.css`。要做矿山安全监测那种深色工业风，改 `.dark` 那组变量即可，**不要动组件**。

## 三、功能架构

### 3.1 页面与权限码

| 路由 | 页面 | 权限码 | 数据来源 | 状态 |
| --- | --- | --- | --- | --- |
| `/login` | LoginPage | 公开 | `POST /api/auth/login` | 真实接口 |
| `/` | PortalPage 门户 | — | 静态 | 完成 |
| `/monitor` | PlaceholderPage | `monitor:view` | 占位 | 待开发 |
| `/components` | ComponentDemoPage | — | `/mock/*` | 组件示例 |
| `/system/users` | UsersPage | `system:user` | `/api/users` | 真实接口（分页/搜索/增删改/启停） |
| `/system/roles` | RolesPage | `system:role` | `/api/roles` | 真实接口（含树形勾选授权） |
| `/system/menus` | MenusPage | `system:menu` | `/api/menus` | 真实接口（三型树表/防成环） |
| `/audit` | PlaceholderPage | `audit:view` | 占位 | 待开发 |
| `/403` `/500` `/:pathMatch(.*)*` | ErrorPage | — | 路由 props | 完成 |

### 3.2 权限三层（同一个权限码贯穿到底）

| 层 | 实现位置 | 行为 |
| --- | --- | --- |
| 菜单级 | `config/menus.ts` 的 `permission` 字段 | 无权限的菜单项直接不渲染 |
| 路由级 | 路由 `meta.permission` + `router.beforeEach` | 未登录跳登录页，无权限跳 `/403` |
| 按钮级 | `v-permission` 指令（静态移除）/ `usePermission()`（响应式） | DOM 层就不存在该按钮 |
| 服务端 | `requirePermission(code)` 中间件实时查库 | 前端可被绕过，服务端是最终闸门 |

数据面：RBAC 六表 `sys_user` / `sys_role` / `sys_menu`（1 目录 2 菜单 3 按钮，parent_id 树形）/ `sys_user_role` / `sys_role_menu`，种子数据 20 条菜单 + admin/inspector 两角色。删除保护三规则（内置对象不可删、角色有绑定拒删、菜单有子节点或绑定拒删）前后端一致。

### 3.3 请求层

`apps/web/src/api/request.ts`：统一 `{ code, data, message }` 契约，`code!==0` 抛 `ApiError`；Bearer 自动注入；15s 超时；401 清本地认证并跳登录（带 redirect）。`/mock/` 前缀走本地 mock 处理器，接完真实后端删掉该分支与 `mock.ts` 即可，业务代码零改动。

## 六、遗留风险与建议（审查时快照；其中 P0 与两条 P1 已于同日实施完成，见第八节）

| 优先级 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| **P0** | 目录不是 git 仓库 | 改错无法回滚，多人协作无基线 | `git init` + 首次提交（`.gitignore` 已就位） |
| **P1** | 包名 `@mo/demo` 与目录 `apps/web` 不一致 | 新人/工具检索易混淆，脚本里 `--workspace @mo/demo` 看着像另一个工程 | 改名 `@mo/web`，同步根 `package.json` 两处脚本 + apps/web 依赖声明 |

| P2 | 数据库口令、JWT 密钥硬编码在 `config.ts` | 上生产即事故 | 抽 `.env.example`，生产强制环境变量 |

| P3 | 端口 5219/3000 散落在 `vite.config.ts`、`config.ts`、`start.bat`、`stop.bat` | 改端口需同步 4 处，漏一处就"起了但打不开" | 收敛到一处（如 `.env`） |

## 七、给后续开发的三条硬规矩

1. **目录/包名一改，先 `npm install`** —— 软链不重建，报错全是"依赖不存在"的假象。
2. **测试/启动报诡异错，先删缓存**（`node_modules/.vite`、`.vitest-*`）—— 比读源码找 bug 快十倍。
3. **新页面四步接入**：`pages/` 建组件 → `router/index.ts` 登记（带 `meta.permission`）→ `config/menus.ts` 登记菜单 → 用 `PageSection` 包裹。
